# 가입전점검

**암보험 상품요약서 한 장으로 하는 가입 전 위험 신호 점검 서비스**

상품요약서(PDF·스캔본·사진)를 올리면 납입보험료와 해약환급률을 한 줄씩 다시 계산하고, 면책기간·유사암 지급비율을 약관 기준과 대조해 판정합니다. 숫자가 틀린 경우에는 보험사에 보낼 정정 확인 요청문을, 자료가 부족한 경우에는 보완 요청문을 함께 만들어 줍니다.

- 팀: IM DU IT
- 엔진: Upstage Studio 워크플로우 (문서 파싱 → 분류 → 정보 추출 → 통합 → 판정 → 안내문)
- 기준 약관: 무배당 AXA암보험(재가입용)2506 (면책기간 90일, 유사암 지급비율 20%)

---

## 1. 왜 필요한가

상품요약서는 가입 전에 소비자가 받는 거의 유일한 요약 문서입니다. 그런데 해약환급금 예시표의 숫자를 직접 검산하는 사람은 드뭅니다. 납입보험료 자리가 바뀌어 적혀 있거나, 환급률이 반올림 범위를 넘어 다르게 적혀 있거나, 면책기간이 약관과 다르게 적혀 있어도 알아채기 어렵습니다. 갱신형인지, 중도 해지 때 돌려받는 돈이 거의 없는 구조인지도 표를 꼼꼼히 봐야 보입니다.

가입전점검은 이 확인 작업을 파일 한 번 올리는 일로 줄입니다.

## 2. 주요 기능

| 기능 | 설명 |
|---|---|
| 문서 업로드 | PDF, JPG, PNG. 스캔본, 사진, 쪽이 나뉘어 들어온 문서도 읽습니다. |
| 플랜별 판정 | 해약환급금 예시표 1개를 플랜 1개로 보고 플랜마다 따로 판정합니다. |
| 계산 근거 공개 | 1·3·5·7·10년 다섯 행의 재계산 과정과 약관 대조 결과를 리포트에서 펼쳐 볼 수 있습니다. |
| 안내문 자동 작성 | 판정에 맞춰 가입 안내, 주의 안내와 설계사 질문, 정정 요청문, 보완 요청문 중 하나를 만듭니다. |
| 리포트 저장 | 복사, 텍스트 저장, 인쇄 또는 PDF 저장을 지원합니다. |
| 예시 리포트 | API 키 없이도 화면과 결과 형식을 볼 수 있습니다. |

## 3. 점검 기준

### 계산 오류 (하나라도 있으면 빨강)
| 코드 | 항목 | 기준 |
|---|---|---|
| E1 | 납입보험료 | 월 보험료 × 12 × 경과연수 = 표의 납입보험료 (다섯 행 모두). 다섯 행이 모두 다른 월 보험료 기준이면 '가입기준 월납 불일치' 한 건으로 봅니다. |
| E2 | 해약환급률 | \|적힌 환급률 − 환급금 ÷ 납입보험료 × 100\| ≤ 0.1%p |
| E3 | 약관 기준 | 면책기간 90일, 유사암 지급비율 20% |

### 가입 전 주의 신호
| 코드 | 신호 |
|---|---|
| S1 | 갱신형 (보험료가 오를 수 있음) |
| S2 | 10년 시점 해약환급금 0 (무해지·저해지 구조) |
| S3 | 3년 환급률 5% 미만 |

### 판정
| 판정 | 화면 표시 | 조건 | 함께 만드는 안내문 |
|---|---|---|---|
| 초록 | 가입 검토 가능 | 계산 오류 없음, 주의 신호 1개 이하 | 가입 안내 3줄 |
| 노랑 | 가입 전 확인 필요 | 계산 오류 없음, 주의 신호 2개 이상 | 신호별 쉬운 설명과 설계사 질문 2개 |
| 빨강 | 정정 요청 필요 | E1·E2·E3 중 하나 이상 | 보험사에 보낼 정정 확인 요청문 |
| 검토 필요 | 자료 보완 필요 | 환급표 쪽이 없거나 읽을 수 없는 칸이 있음 | 담당자 메모와 보완 요청문 |

파일 전체 판정은 플랜 판정 중 가장 무거운 값입니다 (빨강 > 검토 필요 > 노랑 > 초록). 같은 상품의 이전 판 요약서가 섞여 있으면 최신 판만 판정하고 나머지는 제외 목록에 적습니다. 문서에 없는 값은 추측해서 채우지 않습니다.

## 4. 구조

```
[브라우저]  web/index.html
    │  파일 업로드, 3초마다 진행 상태 확인
    ▼
[로컬 서버]  server.py (FastAPI)
    │  /api/diagnose → Upstage에 진단 요청
    │  /api/jobs/{id} → 결과 확인 후 리포트 형태로 정리
    ▼
[Upstage Studio 워크플로우]
    문서 파싱 ─ 분류 ─┬─ 상품요약서 → 정보 추출 → 요약서 통합 → 위험신호_판정
                      │                                         ├─ 초록 → 초록_가입안내
                      │                                         ├─ 노랑 → 노랑_주의안내
                      │                                         ├─ 빨강 → 빨강_정정요청
                      │                                         └─ 검토 필요 → 검토필요_보완요청
                      └─ 그 밖의 문서 → 미분류_안내
```

서버는 파일을 진단 요청에 base64로 바로 실어 보냅니다. 이 방식이 거절되면 파일을 업로드하고 변환이 끝날 때까지(UPLOADED) 기다린 뒤 file_id로 다시 요청합니다. 진단이 끝나면 업로드한 파일을 바로 지웁니다.

## 5. 설치와 실행 (Windows)

### 준비물
- Python 3.9 이상
- Upstage 콘솔에서 발급한 API 키 (`up_`로 시작)
- Studio에서 게시한 워크플로우 ID (`agt_`로 시작)

### 가장 쉬운 방법
`서비스_실행.bat`을 더블클릭합니다. 필요한 패키지를 설치하고 서버를 켠 뒤 브라우저에서 http://localhost:8000 을 엽니다.

### 명령어로 실행
```
cd 가입전점검
py -m pip install -r requirements.txt
py server.py
```
`py`가 없으면 `python`으로 바꿔 실행합니다. 끌 때는 서버 창에서 Ctrl+C를 누릅니다.

### 연결 설정
1. 화면 오른쪽 위 **연결 설정**을 누릅니다.
2. API 키와 워크플로우 ID를 넣고 **연결 확인**을 누릅니다.
3. "연결되었습니다"가 나오면 **저장**합니다.

매번 입력하지 않으려면 이 폴더에 `secrets.toml`을 만들어 둡니다. 이 파일은 공유하거나 제출하지 마세요.
```
UPSTAGE_API_KEY = "up_..."
STUDIO_AGENT_ID = "agt_..."
```

## 6. 사용 방법
1. 상품요약서를 끌어다 놓거나 **파일 선택**으로 올립니다.
2. **점검 시작**을 누릅니다. 보통 1~3분 걸립니다.
3. 리포트에서 판정, 플랜별 결과, 안내문을 확인합니다.
4. 필요하면 안내문을 복사하거나 **인쇄 · PDF 저장**으로 보관합니다.

## 7. 연결 점검 도구

키나 워크플로우 연결이 의심될 때 `키_테스트.bat`을 더블클릭합니다 (또는 `py test_api.py`).

| 단계 | 확인 내용 |
|---|---|
| 1 | 키 형식 (`up_`, 길이, 어디서 읽었는지) |
| 2 | 키 인증 (Solar 1토큰 호출) |
| 3 | Studio 파일 업로드·삭제 |
| 4 | 워크플로우 ID 조회 |
| 5 | 실제 진단 1회 (PDF를 bat 위로 끌어다 놓을 때만), 전체 응답을 `test_result.json`에 저장 |

화면의 키는 앞 5자와 뒤 3자만 보입니다.

## 8. 서버 API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/` | 화면 |
| GET | `/api/config` | 현재 연결 설정 (키는 가려서) |
| POST | `/api/config` | 키·워크플로우 ID 저장 (서버 메모리) |
| POST | `/api/check` | 연결 확인 |
| POST | `/api/diagnose` | 파일 업로드 후 진단 시작, 작업 번호 반환 |
| GET | `/api/jobs/{id}` | 진행 상태, 완료 시 정리된 리포트 데이터 |
| GET | `/api/sample` | 예시 리포트 |

## 9. 검증 결과

해커톤 데이터셋 6세트, 파일 20개, 문서 22건(판정 30플랜: 초록 7, 노랑 12, 빨강 8, 검토 필요 3)을 Studio 워크플로우로 실행해 정답지(`IM DU IT_최종제출_answer.json`)와 대조했습니다. 30플랜 판정이 모두 일치했고, 빨강 사례의 오류 항목과 수치도 정답지와 같았습니다.

| 유형 | 예 |
|---|---|
| 납입보험료 오기 | 7년 2,157,600원 → 25,900 × 84 = 2,175,600원 |
| 환급률 오기 | 3년 5.4% → 41,740 ÷ 993,600 = 4.20% |
| 약관 불일치 | 면책기간 60일(약관 90일), 유사암 10%(약관 20%) |
| 월납 불일치 | 가입기준 29,800원, 예시표는 28,900원 기준 |
| 자료 부족 | 환급표 쪽 누락, 가려진 칸 |

## 10. 개인정보와 보안
- 올린 파일은 진단에만 쓰이고, 진단이 끝나면 Upstage 서버에서 바로 지웁니다.
- 화면에서 입력한 API 키는 이 컴퓨터의 서버 메모리에만 있고, 서버를 끄면 사라집니다.
- 서버는 기본적으로 이 컴퓨터(127.0.0.1)에서만 접속됩니다.

## 11. 한계
- 상품요약서에 적힌 숫자만으로 점검합니다. 최종 가입 조건은 보험사가 발행한 약관과 청약서를 따릅니다.
- 약관 기준값은 무배당 AXA암보험(재가입용)2506 하나입니다. 다른 상품 약관과 비교하려면 판정 기준값을 바꿔야 합니다.
- 진행 단계 표시는 걸린 시간을 기준으로 한 안내입니다. Studio는 단계별 진행률을 따로 주지 않습니다.
- 이 서비스는 참고용 점검 도구이며 보험 가입 권유나 법률 자문이 아닙니다.

## 12. 문제 해결

| 증상 | 해결 |
|---|---|
| `No module named 'requests'` | `py -m pip install -r requirements.txt` 로 설치 (pip와 python이 서로 다른 파이썬을 가리키는 경우) |
| `No module named pip` | `py`로 실행하거나 `python -m ensurepip --upgrade --user` |
| 401 | API 키가 틀렸거나 만료됨. 콘솔에서 다시 복사 |
| 403 No access to file | 서버가 자동으로 두 번째 방식으로 다시 시도합니다. 그래도 나오면 키를 만든 조직과 워크플로우가 있는 조직이 같은지 확인 |
| 404 | 워크플로우 ID 확인 (게시한 워크플로우의 `agt_…`) |
| 화면이 예전 모양 | 새 폴더의 `서비스_실행.bat`으로 실행했는지, 주소가 localhost:8000인지 확인 |
